5. OBSERVATIONS ABOUT BLOCK/MOVEMENT/AI
================================================================================
  - No touch events were captured during this session (game was in menu/idle)
  - The INPUT_DISPATCHER patterns suggest the game polls 4 screen regions 
    per frame — these likely correspond to:
    * Movement joystick (lower-left)
    * Attack button (right side)
    * Block button (lower-center)
    * Special/jump button

  - The game loop at 0x2f0e0 runs at 717/s which is ~12x the expected 60fps.
    This suggests it's called per-entity (717/60 ≈ 12 entities) or does 
    multiple passes per frame.

  - The entity processor at 0x11f0a0 processes heap objects with r0=0x8892,
    which might be a fixed entity class/type identifier.

  - AI system: "TACTICS" string found at 0x8fa96a34 but no AI-specific 
    functions were detected in the hot path during idle gameplay.
    AI functions likely activate only during active combat.

  - Block mechanics: "block" strings found at 0x8fa56bc8 and 0x8fa6d7c7 
    but these are from regex/TIFF library code, NOT game logic.
    The actual game block logic would need to be found via:
    1. Loading ARM binary into Ghidra
