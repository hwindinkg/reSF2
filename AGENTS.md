

## 8. НЕ ОСТАНАВЛИВАТЬСЯ (стоячее указание человека, 25.10)

Остановка работы без внешней причины **запрещена**. Отчёт, сводка, «итог хода»
— **НЕ причина** останавливаться. Признаются только: (1) вопрос, без ответа на
который нельзя продолжить; (2) разрушительная операция, требующая явного «ок»;
(3) исчерпанный бюджет сессии (и тогда — сразу сказать, что именно осталось).
Во всех остальных случаях: закончил задачу → **сразу** бери следующую из
`BUGS.md`/отчётов агентов, чини и проверяй. Не повторяй в отчётах уже
сделанное — пиши только новое.

## 9. ЛИМИТА КОНТЕКСТА НЕТ (стоячее указание человека, 25.10)

«У тебя нет лимита на контекст. За контекстом следит сессия.» Запрещено
ссылаться на «кончился контекст/бюджет» как на причину остановки, сокращать
работу из-за этого или завершать сессию, пока задача не сделана. Каждый раз,
когда хочется остановиться, — вспомнить это правило и продолжить работу.
Остановка возможна только по трём причинам из п.8.

## 10. README: статус обновлять ДО отчёта (стоячее указание человека, 25.10)

README.md — дашборд готовности, его блок между <!-- STATUS:START --> и
<!-- STATUS:END --> ГЕНЕРИРУЕТСЯ: python harness/readme_status.py.
Правила:
1. Перед любым отчётом человеку — python harness/readme_status.py
   (или python harness/gates.py --readme), чтобы цифры в README
   соответствовали дереву. --full обновляет блок сам.
2. python harness/gates.py --check-readme должен быть exit 0; если 1 —
   README устарел, обновить и только потом отчитываться.
3. Цифры готовности НЕ пишутся руками: единственный ручной вход — список
   SYSTEMS в harness/readme_status.py, где каждый False обязан
   соответствовать записанному пробелу в BUGS.md. Нельзя ставить True
   без гейта/замера.
4. README — только готовность, по-английски, без описания проекта.

## 11. ПУШИТЬ ПОСЛЕ КАЖДОГО ЗЕЛЁНОГО ЭТАПА (стоячее указание человека, 25.10)

Неделя без пушей — нарушение. Порядок:
1. python harness/gates.py --full (он сам обновляет README-статус) -> exit 0;
2. python harness/gates.py --check-readme -> exit 0;
3. git push origin harness/gates И git push origin harness/gates:main
   (main — fast-forward, чтобы README-дашборд был на главной странице репозитория);
4. только потом отчёт человеку: в отчёте указать remote-хеш.

Пушить можно обычным git push: credential.helper=manager, в Windows Credential
Manager лежит git:https://hwindinkg@github.com, пароль не спрашивается.
Отдельного API-пути (gh, GITHUB_TOKEN, api.github.com) в проекте нет.
